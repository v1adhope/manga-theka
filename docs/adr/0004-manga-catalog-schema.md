# Manga catalog schema: CHECK-enum collapse, layered chapters/releases/pages, asymmetric localization

The pre-existing `book_types`, `book_statuses`, and `label_types` lookup tables collapse into `CHECK` constraints on `books.kind`, `books.status`, `labels.kind`, per `docs/sql.md`'s "no PG enum type, use check constraints" rule -- these are genuinely closed, small, stable sets (three formats, four statuses, two label kinds; label kinds later grew to three, ADR-0010). `content_ratings` and `languages` stay standalone tables with `GET` list endpoints: rating systems vary by country and the set may grow, and languages are the full ISO 639 list -- neither is a closed enum.

**Three chapter tables, not one**, to support scanlation-style parallel releases:

- `chapters` -- an abstract numbered slot (`book_id`, `number`, `name`, `volume`), no language, no pages;
- `chapter_releases` -- a single-language, single-upload content row;
- `chapter_pages` -- the images of one release.

A release's language is always a translation target, never the book's own `publication_language` (this platform hosts fan-translated releases, not the original-language upload), enforced by a `BEFORE INSERT OR UPDATE OF language_id` trigger `check_chapter_releases_language_not_publication` raising `23514` on a match. This lets one `Chapter Number` hold multiple independent page-sets -- different languages, or competing same-language releases -- as clean FK-linked rows instead of a composite disambiguation key bolted onto a flat table. The release container is fixed after creation (`chapter_id`/`language_id` never change, no `PUT`, no timestamp); its pages mutate as a set -- a commit redeclares the whole order, shifting `sort_order` to stay contiguous from 1, and replacing a page mints a new id (ADR-0006 for the staged-upload-then-commit model; `chapter_pages` also carries no timestamp). `book_covers` deliberately skips this pattern -- no `sort_order`, since a gallery needs one flagged main image, not a reader-facing sequence (ADR-0007).

**`chapters.number` is `real`/`f32`**, not `smallint` (fractional specials, "Chapter 12.5") or `numeric` (avoids the `rust_decimal`/`bigdecimal` dependency `sqlx` would otherwise require). Safe specifically because chapter numbers are write-once literals -- only ever stored, compared, and sorted, never computed -- so accumulated float-rounding error doesn't apply.

**`uploaded_by` is deliberately absent** from `books` and `chapter_releases` for v1: no `users` table exists yet (ADR-0003 designed auth on paper but it was never implemented), and the catalog ships before auth so neither depends on the other's timeline. It'll be added via an additive migration once auth ships. (ADR-0009 later denormalized `book_id` onto `chapter_releases` and `chapter_pages` for its visibility gate.)

**`book_titles` and `chapter_localizations` intentionally use different shapes for similar-looking data.** `book_titles` has composite PK `(book_id, language_id, name)`, allowing any number of rows per `(book_id, language_id)` as long as names differ -- a book can accumulate alternate English names or an original non-English title, an exact repeat is rejected -- with no English row mirrored in, since `books.name` is the canonical English name and `book_titles` holds only additions. `chapter_localizations` keeps composite `(chapter_id, language_id)`, exactly one row per language, English mirrored in: chapter titles have no "many alternate names" case, and the mirror lets a reader-facing "English | original language" title come from one uniform query instead of branching. `chapter_localizations` folds into `POST /books/{id}/chapters` and `PUT /chapters/{id}` -- blind full-array replace, no separate endpoint, no per-row timestamps -- the same way `book_titles` folds into the book body (ADR-0005). This doesn't reintroduce the coupling that keeps titles off `chapter_releases`: resending a chapter's short text rows on every edit is free in a way resending a release's page images is not.
