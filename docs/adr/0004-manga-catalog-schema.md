# The manga catalog schema collapses closed-set lookups to CHECK constraints and layers chapters/releases/pages

**CHECK-enum collapse.** The `book_types`, `book_statuses`, and `label_types` lookup tables collapse into `CHECK` constraints on `books.kind`, `books.status`, `labels.kind` (per `docs/sql.md`): genuinely closed, small, stable sets (three formats, four statuses; label kinds later grew to three, ADR-0010). `content_ratings` and `languages` stay standalone tables with `GET` list endpoints -- rating systems vary by country and may grow, languages are the full ISO 639 list; neither is a closed enum.

**Three chapter tables, not one**, for scanlation-style parallel releases:

- `chapters` -- an abstract numbered slot (`book_id`, `number`, `name`, `volume`); no language, no pages;
- `chapter_releases` -- a single-language, single-upload content row;
- `chapter_pages` -- the images of one release.

A release's language is always a translation target, never the book's `publication_language` (the platform hosts fan-translated releases, not original-language uploads), enforced by a `BEFORE INSERT OR UPDATE OF language_id` trigger `check_chapter_releases_language_not_publication` raising `23514` on a match. So one `Chapter Number` holds multiple independent page-sets -- different languages, or competing same-language releases -- as FK-linked rows, not a composite key bolted onto a flat table. The release container is fixed after creation (`chapter_id`/`language_id` never change, no `PUT`, no timestamp); its pages mutate as a set -- a commit redeclares the whole order, `sort_order` contiguous from 1, replacing a page mints a new id (ADR-0006; `chapter_pages` also carries no timestamp). `book_covers` skips this pattern -- no `sort_order`, since a gallery needs one flagged main image, not a reader-facing sequence (ADR-0007).

**`chapters.number` is `real`/`f32`**, not `smallint` (fractional specials, "Chapter 12.5") or `numeric` (avoids the `rust_decimal`/`bigdecimal` dependency `sqlx` would require). Safe because chapter numbers are write-once literals -- stored, compared, sorted, never computed -- so float-rounding error doesn't accumulate.

**Ownership columns.** `books` and `chapter_releases` carry no `uploaded_by` in v1 (deferred, ADR-0003); `books.created_by` exists (ADR-0009). `chapter_releases` and `chapter_pages` each carry a denormalized `book_id` for ADR-0009's visibility gate, derived from the parent row per insert so it cannot drift.

**`book_titles` and `chapter_localizations` use different shapes for similar-looking data.** `book_titles` has composite PK `(book_id, language_id, name)` -- any number of rows per `(book_id, language_id)` as long as names differ (alternate English names, an original non-English title; an exact repeat is rejected), with no English row mirrored in since `books.name` is the canonical English name and `book_titles` holds only additions. `chapter_localizations` keeps composite `(chapter_id, language_id)`, exactly one row per language, English mirrored in: chapter titles have no "many alternate names" case, and the mirror lets a reader-facing "English | original language" title come from one uniform query with no branching. `chapter_localizations` folds into `POST /books/{id}/chapters` and `PUT /chapters/{id}` -- blind full-array replace, no separate endpoint, no per-row timestamps -- as `book_titles` folds into the book body (ADR-0005). Resending a chapter's short text rows on every edit is free in a way resending a release's page images is not, so this doesn't reintroduce the coupling that keeps titles off `chapter_releases`.
