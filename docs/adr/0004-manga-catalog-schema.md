# Manga catalog schema: CHECK-enum collapse, layered chapters/releases/pages, and asymmetric localization

The pre-existing `book_types`, `book_statuses`, and `label_types` lookup tables collapse into `CHECK` constraints on their owning columns (`books.kind`, `books.status`, `labels.kind`), per `docs/sql.md`'s "no PG enum type, use check constraints" convention -- these are genuinely closed, small, stable sets (three publication formats, four statuses, two label kinds). `content_ratings` and `languages` stay standalone tables with `GET` list endpoints: rating systems vary by country and the project wants room for more than DC Comics' scale later, and the language set is the full ISO 639 list -- neither is a closed enum.

Chapters are modeled across three tables, not one, to support scanlation-style parallel releases: `chapters` is an abstract numbered slot (`book_id`, `number`, `name`, `volume`) with no language and no pages; `chapter_releases` is a single-language, single-upload content row; `chapter_pages` are the images belonging to one release. A release's language is always a translation target, never the book's own `publication_language` -- this platform hosts fan-translated releases, not the original-language upload -- enforced by a `BEFORE INSERT OR UPDATE OF language_id` trigger, `check_chapter_releases_language_not_publication`, raising `23514` on a match. This layering lets the same `Chapter Number` hold multiple independent page-sets -- different languages, or competing releases in the same language -- as clean FK-linked rows, instead of a composite disambiguation key bolted onto a flat `chapters` table. The release container is fixed after creation (`chapter_id`/`language_id` never change, no `PUT`, no timestamp column), but its pages mutate as a set: a commit redeclares the whole order, shifting `sort_order` to stay contiguous from 1. Replacing a page mints a new id rather than updating in place; `chapter_pages` also carries no timestamp column (see ADR-0006 for the staged-upload-then-commit model). `book_covers` deliberately skips this pattern -- no `sort_order`, since a cover gallery needs only one main image flagged, not a reader-facing sequence (see ADR-0007).

`chapters.number` is `real`/`f32`, not `smallint` or `numeric`. Fractional values (specials/omakes, "Chapter 12.5") rule out `smallint`; `real` beats `numeric` to avoid a decimal-type dependency (`rust_decimal`/`bigdecimal`) `sqlx` would otherwise require. Safe specifically because chapter numbers are write-once literals only ever stored, compared, and sorted -- never computed -- so the float-precision risk (accumulated rounding error across arithmetic) doesn't apply.

`uploaded_by` is deliberately absent from `books` and `chapter_releases` for v1: no `users` table exists yet (ADR-0003 designed auth on paper but it was never implemented), and the catalog ships before auth so neither depends on the other's timeline. It'll be added via an additive migration once auth ships.

`book_titles` and `chapter_localizations` intentionally use different shapes for similar-looking data. `book_titles` has composite primary key `(book_id, language_id, name)`, allowing any number of rows per `(book_id, language_id)` as long as names differ -- a book can accumulate several alternate English names or an original non-English title, and an exact repeat is rejected -- with no English row mirrored in, since `books.name` is already the canonical English name and `book_titles` holds only additions. `chapter_localizations` keeps composite `(chapter_id, language_id)`, exactly one row per language, English mirrored in: chapter titles have no "many alternate names" case, and the mirror lets a reader-facing "English | original language" title come from one uniform query instead of branching. `chapter_localizations` folds into `POST /books/{id}/chapters` and `PUT /chapters/{id}` the same way `book_titles` folds into the book body (ADR-0005) -- blind full-array replace, no separate endpoint, no per-row timestamps. This doesn't reintroduce the coupling that keeps titles off `chapter_releases`: resending a chapter's short text rows on every edit is free in a way resending a release's page images is not.
