# Labels become a three-kind curated taxonomy, and publication demographic moves onto books

`labels.kind` grows from `Genre`/`Tag` to `Genre`/`Theme`/`Presentation`, and the seed from 31 sample rows to 70 curated ones -- 27 `Genre`, 38 `Theme`, 5 `Presentation`. The six existing `Tag` rows (`Mafia`, `Music`, `School Life`, `Survival`, `Time Travel`, `Zombies`) are all themes: they keep their ids with `kind` rewritten; the 25 existing genres are untouched. `Tag` disappears as a kind because it never named an axis, only "not a `Genre`" -- a catalog that can't say whether `Long Strip` describes a subject or a shape pushes that distinction into every client's picker. This edits the original `20260629101118_add_labels` migration in place (keeping `on conflict(name) do update` so a re-run stays idempotent).

**The third kind is `Presentation`, not `Format`**, because `CONTEXT.md` defines `Book Kind` as "the publication format" and lists `Format` under its `_Avoid_`. `Presentation` is deliberately broad (how a `Book` is packaged *or* where it came from) and holds five values: `Long Strip`, `Full Color`, `Oneshot`, `Adaptation`, `Self-Published`. The first three are load-bearing -- a long-strip webtoon reads differently from a paged book, `Full Color` is a property of the original manhwa work not any one upload, `Oneshot` answers "something I can finish tonight" -- and no other column captures them. `Adaptation` and `Self-Published` are provenance rather than packaging; a fourth kind for two values would cost a `CHECK` value, an API concept, and a UI section, so the broad definition absorbs them. Caveat: if a reader client ever needs `Long Strip` to *choose a rendering mode* rather than to filter, that is a `books` column, not a label, and would arrive as an additive migration without disturbing this kind.

**Seven values were added on top of the base vocabulary**, which is Japan-centric while `Book Kind` commits this catalog to Manhwa and Manhua. `Xianxia` and `Murim` join `Genre`: `Wuxia` was the only Chinese-native genre present and covers neither cultivation fantasy nor the Korean martial world, both large categories here. `Regression`, `Dungeons`, `Game System`, `Revenge`, `Super Powers` join `Theme`, each because an existing value looked like it covered the ground and doesn't: `Regression` (dying and returning to one's own past) is neither `Time Travel` nor `Reincarnation`; `Dungeons` is not `Isekai`, the protagonist never leaves their world; `Game System` (game mechanics literally real) is neither `Video Games` nor `Virtual Reality`; `Super Powers` covers powers without the Western `Superhero` idiom; `Revenge`, a dominant driver here, had none. `Traditional Games` was renamed `Strategy Games` -- accurate for go/shogi/karuta but near-meaningless to an English reader; the rename widens to chess and card games, the cheaper error.

**Eight base-vocabulary values were rejected**, in four groups:

- `Loli`, `Shota`, `Incest` -- content-policy: in several jurisdictions the first two name material illegal to host regardless of labeling, and a curated label shapes what gets submitted *before* `Book Visibility` review sees it.
- `Fan Colored`, `Official Colored` -- wrong entity: colorization is a property of one scanlation group's upload (a `Chapter Release`), false the moment a second, uncolored release exists. `Full Color` survives because for manhwa it describes the original work.
- `Award Winning` -- unverifiable, unmaintainable (which award, which year, by whom), and uncorrectable with no label CRUD.
- `User Created` -- specific to another platform's model. `Gyaru` -- opaque to an English-first audience, and a character type rather than a theme.

*Rejected: a fourth kind for content warnings (`Gore`, `Sexual Violence`). `Content Rating` is already the audience-suitability signal, exactly one per `Book`, and a second overlapping axis invites disagreement. Recorded because it gets reopened without context: a reader cannot filter *out* graphic content while still reading `Mature` titles, since the only lever is the rating itself. If that matters, the answer is a fourth `Label Kind`, not folding warnings into `Theme` where "exclude gore" would be indistinguishable from "exclude cooking".*

*Rejected: a `code`/slug column on `labels`. Tempting because `content_ratings` and `languages` carry one, and it would make filter query strings readable. Rejected because labels stay read-only and migration-seeded, and a client fetches `GET /labels` to build a picker before filtering -- so nothing is blocked by ids, and a second identifier is a second thing to keep unique and stable. Accepted consequence: filter query strings are UUID soup and any filter-bug investigation begins with `GET /labels`. `labels.id` stays the only identifier.*

**No label CRUD and no `retired_at`**, both deferred to the enum-CRUD issue. They belong together: with no write endpoint nothing can retire a label, and `book_labels.label_id` is `on delete restrict` so a referenced label can't be deleted anyway. Whoever builds that endpoint owns retirement, and should reach for a `retired_at timestamptz` that hides a label from pickers and filters while leaving existing attachments intact, not a delete the FK will refuse.

**`books` gains `publication_demographic`** -- a `not null` `text` column constrained by `enum_books_publication_demographic` to `Shounen`, `Shoujo`, `Seinen`, `Josei`, `Kids`, joining the original `20260629100955_add_books` migration in place. A column rather than a fourth `Label Kind` because it is a closed set with exactly one value per `Book`, and a label cannot enforce that cardinality (the reasoning ADR-0004 used to collapse `kind`/`status` into `CHECK` constraints). Mandatory, joining `kind`, `status`, `content_rating_id`, `publication_language_id`, so the `GET /books` facet partitions the whole catalog with no unpickable remainder. *Rejected: a nullable column, and an `Unknown` member -- each reintroduces a sixth non-answer state, differing only in spelling.* Value supplied by code on every insert (`docs/sql.md` bans defaults). Accepted cost: a work whose original publisher marketed to no demographic (self-published manhwa most of all) carries a best-fit judgement; correcting one is an ordinary metadata edit on a `Listed` `Book`, and `Feedback` of kind `Correction` is the dispute channel. `Kids` is included -- real for manga, harmless for manhwa.

*Rejected: folding demographic into `Content Rating`. `Content Rating` describes what is in a book, demographic the readership its original publisher marketed to -- many-to-many in both directions (a `Seinen` work can be rated `Everyone`, a `Shounen` work `Mature`), so collapsing them means a reader filtering `Mature` for seinen gets shounen back.*
