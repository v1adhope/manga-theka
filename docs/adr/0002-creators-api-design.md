# Creators API: plural REST with `{data}` envelope and UUID-v7 cursor pagination

The creators API uses plural REST routes (`/creators`, `/creators/{id}`) with a uniform `{data: ...}` response envelope across all endpoints — including the existing `POST /creators`, which was migrated from the singular `/creator` path with a bare `{id}` body. Responses wrap payloads in `{data}` so single-item, list, and create-acknowledgement responses share one shape; `nextCursor` is always present (no `skip_serializing_if`) and is `null` at end of list.

List pagination is cursor-based on the raw UUID v7 id (`?after=<uuid>&limit=<n>`, `WHERE id < $after ORDER BY id DESC`), over-fetching by one row to detect the next page in a single query. The v7 id encodes creation time, so ordering by id is equivalent to ordering by `created_at` with no ties possible — a separate `created_at` cursor was rejected as redundant. Opaque/base64 cursors were rejected in favor of raw UUIDs for debuggability while no client depends on the wire format yet.

Input validation splits by failure level: syntax/parse errors (malformed UUID, non-integer limit) return 400 via axum's default query/JSON rejection; semantic violations (limit out of `[1, 100]`, name not letters-only) return 422; a duplicate full name returns 409 per RFC 9110 §15.5.10, which scopes 409 to conflicts with the target resource's current state and leaves 422 for content-shape violations. PUT and DELETE detect missing rows via a `RETURNING id` clause (single round-trip) and map `None` to `DatabaseError::CreatorNotFound` → 404 (forwarded transparently by `ServiceError`) with a plain-text `"Creator not found"` body, matching the existing `DatabaseError` plain-text response convention. PUT keeps `created_at` immutable by omitting it from the `UPDATE` SET clause; the route constructs the `Creator` value with a `UNIX_EPOCH` placeholder for the ignored field, preserving the non-Option entity invariant. Timestamps serialize as RFC 3339 via `time::serde::rfc3339` directly on the `Creator` entity (no separate DTO); `Name` serializes as its inner string through `#[serde(transparent)]`, while `Uuid` and `CreatorRole` remain typed.
