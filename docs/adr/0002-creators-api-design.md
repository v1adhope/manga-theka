# Creators API: plural REST with `{data}` envelope and UUID-v7 cursor pagination

Plural REST routes (`/creators`, `/creators/{id}`) with a uniform `{data: ...}` envelope on every endpoint, including `POST /creators` (migrated from the singular `/creator` with a bare `{id}` body). The envelope lets single-item, list, and create-ack responses share one shape; `nextCursor` is always present (no `skip_serializing_if`), `null` at end of list.

List pagination is cursor-based on the raw UUID v7 id (`?after=<uuid>&limit=<n>`, `WHERE id < $after ORDER BY id DESC`), over-fetching one row to detect the next page in a single query. A v7 id encodes creation time, so ordering by id equals ordering by `created_at` with no ties -- a separate `created_at` cursor would be redundant. Opaque/base64 cursors were rejected while no client depends on the wire format, favoring debuggability. **Superseded for `GET /books` by ADR-0011**, which needs an opaque composite cursor because its non-unique sort keys (name, publication year) cannot page on a bare id; this endpoint is unchanged.

Validation splits by failure level: parse errors (malformed UUID, non-integer limit) return 400 via axum's default rejection; semantic violations (limit outside `[1, 100]`, name not letters-only) return 422; a duplicate full name returns 409 per RFC 9110 §15.5.10, which scopes 409 to conflicts with the resource's current state and reserves 422 for content-shape violations. PUT and DELETE detect missing rows with a `RETURNING id` clause (one round-trip), mapping `None` to `DatabaseError::not_found::<Creator>()` -> 404 with a plain-text `"Creator not found"` body, matching the `DatabaseError` convention. PUT keeps `created_at` immutable by omitting it from the `UPDATE` SET clause; the route builds `Creator` with a `UNIX_EPOCH` placeholder for that field to preserve the non-`Option` entity invariant.

Timestamps serialize as RFC 3339 via `time::serde::rfc3339` directly on `Creator` (no DTO); `Name` serializes as its inner string via `#[serde(transparent)]`; `Uuid` stays typed. `Creator` is identity only (`id`, `first_name`, `last_name`, `created_at`), no `role`: the same person is routinely credited as both Artist and Author, so `CreatorRole` lives on the `book_creators` relation (see ADR-0005).
